# Питання для самоперевірки — Lesson 14: Fixture Best Practices

## 🧩 Ізоляція

1. **Чому function-scope дає ізоляцію за замовчуванням?**
   - Коли створюється фікстура з `scope="function"`?
   - Що станеться, якщо один тест змінить дані фікстури?

2. **Чому ізольовані тести можна запускати в будь-якому порядку?**
   - Що означає «тест не залежить від сусіда»?
   - Як ізоляція допомагає при паралельному запуску?

## 📏 Scope

3. **Який scope брати за замовчуванням і чому?**
   - Коли варто розширити scope до `module`/`session`?
   - Наведіть приклад ресурсу, для якого ширший scope виправданий.

4. **Який головний ризик ширшого scope?**
   - Чому session-scope швидший, але небезпечніший?
   - Як зробити ширший scope безпечним? (підказка: read-only)

## 🎯 Одна відповідальність та імена

5. **Чому фікстура-«комбайн» — погано?**
   - Що складніше при дебагу, коли одна фікстура робить усе?
   - Як розбити її на менші?

6. **Чому `sample_admin_user` краще за `data`?**
   - Що ім'я фікстури має пояснювати?
   - Як зрозуміле ім'я допомагає читати сигнатуру тесту?

7. **Що таке композиція фікстур?**
   - Як фікстура `client(user)` використовує `user`?
   - Яка перевага шарів `user → client → authed_session`?

## 🪄 autouse

8. **Що робить `autouse=True`?**
   - До яких тестів застосовується така фікстура?
   - Чому це називають «прихованою магією»?

9. **Коли `autouse` доречний, а коли ні?**
   - Наведіть приклад доречного використання (housekeeping).
   - Наведіть приклад, де краще передати фікстуру явно.
