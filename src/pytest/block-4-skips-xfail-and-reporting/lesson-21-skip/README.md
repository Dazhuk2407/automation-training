## 📖 Теорія

### 1. Навіщо пропускати тести

Іноді тест **не має сенсу виконувати прямо зараз**, але видаляти його теж не можна:

- **Фіча ще не готова** — код під тест ще не написаний, але тест уже є.
- **Залежність від платформи** — тест має сенс лише на Windows / Linux / macOS.
- **Зовнішній ресурс недоступний** — немає підключення до БД, API, змінної оточення.
- **Версія Python / бібліотеки** — фіча існує лише з певної версії.

Пропущений тест **не є падінням**. У звіті він рахується окремо (`skipped`), а exit code лишається `0`. Це головна відмінність від закоментованого тесту: skip **видно** у звіті, а закоментований код — ні.

---

### 2. `@pytest.mark.skip` — пропустити завжди

Найпростіший спосіб — маркер над функцією:

```python
import pytest

@pytest.mark.skip(reason="фіча ще не реалізована")
def test_new_feature():
    assert new_feature() == 42  # не виконається — тест пропущено
```

Тест **ніколи не виконується**, поки маркер на місці. У звіті:

```
test_new_feature SKIPPED (фіча ще не реалізована)
```

---

### 3. `@pytest.mark.skipif` — пропустити за умовою

Пропуск лише коли умова істинна. Умова обчислюється під час збору тестів:

```python
import sys
import pytest

@pytest.mark.skipif(
    sys.version_info < (3, 12),
    reason="потрібен Python 3.12+",
)
def test_new_syntax():
    assert True
```

Якщо умова `True` — тест пропускається. Якщо `False` — виконується як звичайно.

Умовою може бути будь-який булевий вираз: версія Python, платформа, наявність змінної оточення тощо.

```python
import os

@pytest.mark.skipif(
    os.getenv("DB_URL") is None,
    reason="немає підключення до БД",
)
def test_db_query():
    ...
```

---

### 4. Імперативний `pytest.skip()` всередині тесту

Коли умову можна перевірити лише **під час виконання** (динамічно) — викликайте `pytest.skip()` прямо в тілі:

```python
import pytest

def test_reads_config():
    config = load_config()
    if config is None:
        pytest.skip("конфіг недоступний у цьому середовищі")
    assert config["enabled"] is True
```

Як тільки виконано `pytest.skip(...)`, решта тесту **не виконується** — він одразу позначається як `skipped`. Це зручно коли рішення про пропуск залежить від даних, отриманих уже в тесті.

---

### 5. `reason` — обовʼязковий

Завжди вказуйте `reason`. Це не формальність:

```python
# ❌ Погано — незрозуміло чому пропущено
@pytest.mark.skip
def test_something():
    ...

# ✅ Добре — причина видима у звіті
@pytest.mark.skip(reason="блокує баг #1234, чекаємо фікс")
def test_something():
    ...
```

З `-rs` pytest показує причини всіх пропусків:

```
pytest -rs
...
SKIPPED [1] test_file.py:10: блокує баг #1234, чекаємо фікс
```

Без `reason` через півроку ніхто не згадає, чому тест вимкнено.

---

### 6. skip vs xfail (коротко)

| | `skip` | `xfail` |
|---|--------|---------|
| Що означає | «не виконуй цей тест» | «очікую що впаде» |
| Тіло виконується | ❌ ні | ✅ так (але падіння не рахується) |
| Коли | фіча не готова, не та платформа | відомий баг, який ще не пофіксили |

**Skip** взагалі не запускає тіло. **Xfail** запускає, але дозволяє падіння. Деталі — у Lesson 22.

---

### 7. Skip у роботі QA

- **Ще не реалізований API** — endpoint у розробці, тест уже написано → `skip` до релізу.
- **Платформо-залежні перевірки** — тест шляхів файлів лише для Windows → `skipif(sys.platform != "win32", ...)`.
- **Зовнішні залежності** — інтеграційний тест потребує тестового стенду → `skipif(env is None, ...)`.
- **Флейкі середовище** — ресурс тимчасово недоступний → імперативний `pytest.skip()` після перевірки.

Skip тримає тест **живим і видимим**: він у наборі, у звіті, з причиною — а не втрачений у закоментованому коді.

## ⚠️ Типові помилки

### Skip без reason

```python
# ❌ У звіті не буде видно причину
@pytest.mark.skip
def test_x():
    ...

# ✅
@pytest.mark.skip(reason="фіча ще не готова")
def test_x():
    ...
```

### `skipif` з передчасно обчисленою умовою

`skipif` приймає **вираз-умову**, а не результат виклику з побічними ефектами. Передавайте булевий вираз:

```python
# ❌ Не викликайте функцію, що має бути частиною тесту
@pytest.mark.skipif(do_heavy_setup(), reason="...")
def test_x():
    ...

# ✅ Простий булевий вираз
@pytest.mark.skipif(sys.version_info < (3, 12), reason="потрібен 3.12+")
def test_x():
    ...
```

### Закоментувати тест замість skip

```python
# ❌ Тест зникає зі звіту — про нього забудуть
# def test_new_feature():
#     assert new_feature() == 42

# ✅ Тест лишається видимим, з причиною
@pytest.mark.skip(reason="фіча ще не реалізована")
def test_new_feature():
    assert new_feature() == 42
```
