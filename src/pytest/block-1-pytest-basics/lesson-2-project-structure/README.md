## 📖 Теорія

### 1. Структура проєкту

Стандартна структура pytest проєкту:

```
my_project/
├── src/                    # Код програми
│   ├── __init__.py
│   └── calculator.py
├── tests/                  # Тести
│   ├── __init__.py
│   ├── conftest.py         # Конфігурація pytest
│   └── test_calculator.py
├── requirements.txt        # Залежності (див. Lesson 1)
├── pytest.ini              # Налаштування pytest
└── README.md
```

---

### 2. Чому код і тести розділяють

| Аспект | Чому важливо |
|--------|-------------|
| **Чистота** | Тести не потрапляють у production збірку |
| **Навігація** | Розробник одразу знає де шукати тести |
| **CI/CD** | Можна запускати тести окремо від коду |
| **Масштабування** | Тести ростуть незалежно від коду |

**Правило:** код живе в `src/`, тести живуть в `tests/`. Ніколи їх не змішуйте.

Якщо покласти тести поруч з кодом (`src/test_calculator.py`), вони потраплять у production пакет, ускладнять навігацію, і запустити `pytest tests/` буде неможливо.

---

### 3. Роль кожної папки та файлу

**`src/`** — код програми. Тут живуть модулі, які ви тестуєте.

**`tests/`** — тести. Кожен тестовий файл починається з `test_` і відповідає модулю з `src/`:
- `src/calculator.py` → `tests/test_calculator.py`
- `src/auth.py` → `tests/test_auth.py`

**`__init__.py`** — порожній файл, який робить папку Python-пакетом. Потрібен для правильного імпорту.

**`conftest.py`** — спеціальний файл, який pytest підхоплює автоматично (див. секцію 5).

**`pytest.ini`** — налаштування запуску pytest (див. секцію 4).

---

### 4. pytest.ini

Файл `pytest.ini` — це **конфігурація pytest**. Він не обов'язковий, але використовується в більшості реальних проєктів.

**Навіщо потрібен:**
- Стандартизує запуск тестів для всієї команди
- Не потрібно кожен раз вводити опції вручну
- CI/CD використовує ті самі налаштування

```ini
[pytest]
# Де шукати тести
testpaths = tests

# Які файли вважати тестовими
python_files = test_*.py

# Які класи вважати тестовими
python_classes = Test*

# Які функції вважати тестовими
python_functions = test_*

# Опції за замовчуванням (-v = verbose, --tb=short = коротший traceback)
addopts = -v --tb=short
```

**Що це дає:** замість `pytest tests/ -v --tb=short` достатньо написати `pytest`.

---

### 5. conftest.py

`conftest.py` — спеціальний файл, який pytest знаходить і підхоплює автоматично.

**Для чого використовується:**
- Спільна конфігурація для всіх тестів
- Фікстури (будемо вивчати пізніше)
- Хуки pytest

На цьому етапі достатньо створити заглушку:

```python
"""
conftest.py — конфігурація pytest.

Цей файл автоматично підхоплюється pytest.
Тут буде спільна конфігурація та фікстури (розглянемо пізніше).
"""
```

**Важливо:** `conftest.py` **не потрібно імпортувати** — pytest знаходить його сам. Не обов'язковий для простих проєктів, але стандарт у реальних.

---

### 6. Створення структури

Створити структуру можна вручну в IDE або через термінал:

```bash
# Створити кореневу папку проєкту
mkdir my_project
cd my_project

# Створити директорії
mkdir src tests

# Створити __init__.py
touch src/__init__.py
touch tests/__init__.py

# Створити конфігурацію
touch pytest.ini
touch tests/conftest.py
```

Або просто створіть ці папки та файли в PyCharm / VS Code — результат однаковий.

---

## ⚠️ Типові помилки

| Помилка | Наслідок |
|---------|----------|
| Тести в `src/` | Потрапляють у production, ускладнюють збірку |
| Немає `__init__.py` в `tests/` | Помилки імпорту між тестовими файлами |
| Немає `pytest.ini` | Кожен запускає тести з різними опціями |
| `conftest.py` не в `tests/` | pytest не підхопить його автоматично |
