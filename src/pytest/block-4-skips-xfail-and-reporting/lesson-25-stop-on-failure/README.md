## 📖 Теорія

### 1. `pytest -x` — зупинитись на ПЕРШІЙ помилці

За замовчуванням pytest виконує **весь** набір тестів, навіть якщо перший тест впав. Прапорець `-x` каже зупинитись одразу після першого падіння:

```bash
pytest -x
```

Що це дає: якщо тест №1 впав, тести №2, №3, ... **не виконуються**. Ви бачите результат миттєво, а не через кілька хвилин.

`-x` — це скорочення для `--maxfail=1`:

```bash
pytest -x
pytest --maxfail=1
```

Обидві команди роблять абсолютно те саме — зупиняються після **однієї** помилки.

---

### 2. `--maxfail=N` — зупинитись після N помилок

Іноді одна помилка — замало, а весь набір — забагато. `--maxfail=N` зупиняє прогін, коли накопичилось **N** падінь:

```bash
pytest --maxfail=3
```

Прогін триває, поки не набереться 3 падіння. Після третього — зупинка, решта тестів не виконуються. Тести, що проходять, помилки **не** збільшують — рахуються лише падіння.

---

### 3. Навіщо це потрібно

Уявіть набір із 500 тестів. Ви зламали щось спільне (наприклад, конфіг чи імпорт) — і **все** червоне.

Без `-x`: чекаєте кілька хвилин, доки відпрацюють усі 500, щоб побачити те, що і так очевидно.

З `-x`: pytest падає на першому тесті, ви одразу бачите причину, виправляєте — і запускаєте знову. Цикл **фікс → повтор** стає набагато коротшим.

```bash
# Швидкий цикл під час активного дебагу:
pytest -x        # впало на першому — читаємо помилку
# ... виправляємо код ...
pytest -x        # знову — і так до зеленого
```

---

### 4. Компроміс: менше даних за один прогін

`-x` показує лише **першу** проблему. Якщо у вас 10 незалежних падінь, за один прогін ви побачите тільки одне з них.

| Прапорець | Що бачите за прогін | Коли доречно |
|-----------|--------------------|--------------|
| (без) | ВСІ падіння | Хочете повну картину |
| `-x` | Лише ПЕРШЕ падіння | Все масово червоне, дебаг |
| `--maxfail=3` | До 3 падінь | Компроміс між швидкістю і картиною |

Тобто `-x` — це вибір **швидкості** ціною **повноти**. Коли треба зібрати повний список того, що зламано — `-x` не ставте.

---

### 5. Комбінації з `--lf` / `--ff`

`-x` чудово поєднується з прапорцями порядку/фільтрації з попередніх уроків:

```bash
pytest --lf -x   # тільки раніше впалі тести, зупинка на першому
pytest --ff -x   # спершу раніше впалі, потім решта; зупинка на першому
```

- `--lf -x` — перезапустити лише те, що падало, і зупинитись на першому, що досі червоне. Найкоротший цикл дебагу.
- `--ff -x` — почати з раніше впалих (щоб швидше натрапити на проблему), і зупинитись на першому падінні.

Важливо: `-x` **не змінює порядок** тестів. Порядок задають `--ff` / `--lf` (чи звичайний порядок збору). `-x` лише **зупиняє** прогін.

---

### 6. У QA-практиці

- **Локальний дебаг**: коли масово червоно — `pytest -x` дає миттєвий фідбек, не чекаючи весь набір.
- **CI fail-fast**: у пайплайні `--maxfail=1` (або невелике N) економить час і ресурси — немає сенсу ганяти повний набір, якщо збірка вже зламана.
- **Нічний повний прогін**: тут `-x` **не** потрібен — навпаки, хочете зібрати ВСІ падіння за один раз.

## ⚠️ Типові помилки

### `-x` коли треба побачити ВСІ падіння

```bash
# ❌ Хочете повний список зламаного, але зупиняєтесь на першому
pytest -x
# ✅ Дайте прогону завершитись — побачите всі падіння
pytest
```

### Плутати `-x` і `-k`

```bash
# ❌ -x НЕ фільтрує тести за назвою
pytest -x login          # login тут сприймається як шлях/аргумент, не фільтр

# ✅ Для вибору тестів за назвою — -k
pytest -k login          # запустити тести, у назві яких є "login"
# ✅ Можна поєднати: відфільтрувати і зупинитись на першому
pytest -k login -x
```

`-x` = **зупинка** на помилці. `-k` = **вибір** тестів за виразом. Це різні речі.

### Думати, що `-x` впливає на порядок

```bash
# ❌ Хибне уявлення: "-x запускає впалі першими"
# Ні. -x лише зупиняє прогін. Порядок задають --ff / --lf.
pytest --ff -x   # ✅ порядок від --ff, зупинка від -x
```
