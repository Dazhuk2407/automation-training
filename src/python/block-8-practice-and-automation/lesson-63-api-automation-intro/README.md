## 📖 Теорія

### 1. Що таке API-автоматизація

API-автоматизація — це перевірка бекенду **напряму через HTTP**, без UI.
Замість того щоб клікати кнопки у браузері, тест надсилає запит на сервер і
перевіряє відповідь.

Переваги над UI-тестами:
- **Швидше** — немає рендерингу сторінки, немає очікувань анімацій.
- **Стабільніше** — не залежить від верстки, локаторів, timing-проблем.
- **Ближче до логіки** — тестуємо саме контракт бекенду.

Типовий цикл: надіслати запит → отримати відповідь (статус + тіло) → перевірити.

---

### 2. HTTP методи

Метод описує **намір** операції над ресурсом:

| Метод    | Призначення           | Приклад                     |
|----------|-----------------------|-----------------------------|
| `GET`    | читання               | отримати користувача        |
| `POST`   | створення             | створити користувача        |
| `PUT`    | повне оновлення       | замінити користувача цілком |
| `PATCH`  | часткове оновлення    | змінити одне поле           |
| `DELETE` | видалення             | видалити користувача        |

**Ідемпотентність** (коротко) — повторний виклик дає той самий результат.
`GET`, `PUT`, `DELETE` — ідемпотентні; `POST` — ні (кожен виклик створює новий ресурс).

---

### 3. Статус-коди

Сервер повертає числовий код. Клас визначається **першою цифрою**:

| Клас  | Значення              | Приклади                          |
|-------|-----------------------|-----------------------------------|
| `2xx` | успіх                 | 200 OK, 201 Created, 204 No Content |
| `3xx` | редірект              | 301 Moved, 304 Not Modified       |
| `4xx` | помилка клієнта       | 400, 401, 403, 404                |
| `5xx` | помилка сервера       | 500, 502, 503                     |

Класифікація за першою цифрою:

```python
def status_class(code):
    """Клас статус-коду: 200 -> '2xx', 404 -> '4xx'."""
    return f"{code // 100}xx"
```

---

### 4. Заголовки й тіло

**Заголовки** (headers) передають метадані запиту:
- `Content-Type: application/json` — формат тіла.
- `Authorization: Bearer <token>` — токен авторизації.

**Тіло** (body) для `POST`/`PUT` зазвичай передається як JSON.

> ⚠️ **Токени НІКОЛИ не хардкодимо.** Читаємо з оточення:

```python
import os

def build_auth_header():
    """Заголовок авторизації з токеном з env."""
    token = os.getenv("API_TOKEN", "")
    return {"Authorization": f"Bearer {token}"}
```

---

### 5. Бібліотека `requests` (оглядово)

У реальних проєктах запити виконує бібліотека `requests`.
Це **довідка** — код нижче НЕ виконуємо в цьому уроці (потрібні мережа та встановлений пакет):

```python
# Довідка (не виконувати):
import requests

resp = requests.get("https://api.example.com/users", headers={"Authorization": "Bearer ..."})
resp.status_code   # 200
resp.json()        # {"users": [...]}

requests.post("https://api.example.com/users", json={"name": "Alice"})
```

У прикладах цього уроку замість реальної мережі ми використовуємо **власний mock-клієнт**.

---

### 6. Будова API-тесту

Класична структура **arrange → act → assert**:

```python
def test_get_user():
    # arrange — підготувати дані/клієнта
    client = MockApiClient({"/users/1": {"status": 200, "json": {"id": 1, "name": "Alice"}}})

    # act — виконати запит
    resp = client.get("/users/1")

    # assert — перевірити статус + поля відповіді
    assert resp["status"] == 200
    assert resp["json"]["name"] == "Alice"
```

---

### 7. Куди далі

Після цього вступу реальна API-автоматизація будується так:
- **pytest + requests** — справжні запити у тестах.
- **Схеми відповідей** — валідація структури JSON (напр. `jsonschema`, `pydantic`).
- **Авторизація** — токени/сесії, читання секретів з env або сховища.
- **CI** — запуск API-тестів на кожен pull request.

## ⚠️ Типові помилки

### Хардкод секретів

```python
# ❌ НІКОЛИ так не роби
headers = {"Authorization": "Bearer sk_live_1234567890"}

# ✅ Читай з оточення
import os
headers = {"Authorization": f"Bearer {os.getenv('API_TOKEN', '')}"}
```

### Перевірка лише статусу

```python
# ❌ Мало — 200 не гарантує правильні дані
assert resp["status"] == 200

# ✅ Перевіряй також тіло відповіді
assert resp["status"] == 200
assert resp["json"]["id"] == 1
```
