# Lesson 19: Filter Tests by Name (pytest -k)

## 🎯 Learning Outcomes

Після цього уроку ви зможете:

- ✅ Запускати тести за підрядком імені: `pytest -k login`
- ✅ Використовувати вирази: `-k "login and not admin"`, `-k "login or logout"`
- ✅ Розуміти що `-k` матчить **імена** тестів, а не маркери
- ✅ Комбінувати `-k` та `-m` в одному запуску
- ✅ Іменувати тести так, щоб `-k` був зручним інструментом

---

## 📋 Передумови

Ви вже знаєте:
- Що таке маркери (`@pytest.mark.smoke`) — Lesson 17
- Як фільтрувати тести за маркером через `-m` — Lesson 18

`-m` фільтрує за **маркерами**. Цей урок — про `-k`, який фільтрує за **іменами**.

---

## 📖 Теорія

### 1. `pytest -k` — запуск за підрядком імені

Прапорець `-k` запускає лише ті тести, чиє **ім'я** містить заданий підрядок:

```bash
# Запустити всі тести, в імені яких є "login"
pytest -k login
```

Якщо у файлі є `test_login_valid`, `test_login_invalid`, `test_logout`, `test_signup`,
то `-k login` запустить перші два (обидва містять підрядок `login`), а решту пропустить (deselected).

Матчинг **регістронезалежний**: `-k LOGIN` знайде `test_login_valid`.

---

### 2. Вирази у `-k`

`-k` приймає не лише підрядок, а й **логічний вираз** з операторами `and`, `or`, `not`:

```bash
# login, але НЕ admin
pytest -k "login and not admin"

# login АБО logout
pytest -k "login or logout"

# усе, крім повільних
pytest -k "not slow"
```

- `and` — обидва підрядки мають бути в імені
- `or` — хоча б один підрядок в імені
- `not` — підрядка НЕ має бути в імені

Вираз беруть у лапки, бо він містить пробіли.

---

### 3. `-k` матчить ІМЕНА, а не маркери

Це ключовий момент. `-k` дивиться на **підрядок у назві**:
- функції тесту (`test_login_valid`)
- класу (`TestLoginFlow`)
- файлу/модуля (`test_auth.py`)

`-k` **не знає нічого про маркери**. Навіть якщо тест позначено `@pytest.mark.login`,
команда `-k login` матчить його лише тому, що підрядок `login` є в **імені**, а не через маркер.

| Прапорець | Що фільтрує | Приклад |
|-----------|-------------|---------|
| `-k` | підрядок в **імені** тесту/класу/файлу | `pytest -k login` |
| `-m` | **маркер** (`@pytest.mark.<name>`) | `pytest -m smoke` |

Якщо позначити тест `@pytest.mark.slow`, то `-m slow` його знайде, а `-k slow` — **ні**
(бо в імені `test_big_upload` немає підрядка `slow`).

---

### 4. Комбінування `-k` та `-m`

`-k` та `-m` можна вказати разом — застосуються **обидва** фільтри (логічне І):

```bash
# smoke-тести, в імені яких є "login"
pytest -m smoke -k login
```

Запуститься тест, який одночасно:
- позначено маркером `smoke` (умова `-m`)
- має підрядок `login` в імені (умова `-k`)

Це зручно: `-m` звужує до категорії, `-k` — до конкретної фічі.

---

### 5. Іменування тестів під зручний `-k`

`-k` настільки корисний, наскільки продумані ваші імена. Послідовний **префікс фічі** робить фільтрацію тривіальною:

```python
# ✅ Зрозумілий, послідовний неймінг — -k login забере всю фічу
def test_login_valid(): ...
def test_login_invalid_password(): ...
def test_login_locked_account(): ...

# ❌ Хаотичний неймінг — -k login пропустить частину
def test_login_valid(): ...
def test_auth_wrong_pw(): ...      # про login, але без "login" в імені
def test_case_42(): ...            # незрозуміло про що
```

Домовтесь у команді про єдину схему імен (наприклад `test_<feature>_<case>`) —
і `-k <feature>` завжди даватиме передбачувану підмножину.

---

### 6. `-k` у роботі QA

Типовий сценарій: ви дебажите **одну фічу** і не хочете ганяти весь suite на 2000 тестів.

```bash
# Швидкий цикл під час роботи над login
pytest -k login -q

# Дебаг однієї групи негативних кейсів
pytest -k "login and invalid" -vv
```

`-k` дає миттєвий feedback loop: змінили код → прогнали лише релевантні тести → повторили.
Повний suite залишаєте на CI.

## ⚠️ Типові помилки

### `-k` не працює з маркерами

```bash
# ❌ Очікувати що -k знайде тести за маркером @pytest.mark.slow
pytest -k slow      # знайде лише тести, в ІМЕНІ яких є "slow"
# ✅ Для маркера — використовуйте -m
pytest -m slow
```

### Занадто загальний підрядок

```bash
# ❌ "log" зачепить і login, і logout, і test_logger, і catalog
pytest -k log
# ✅ Конкретніше
pytest -k "login and not logout"
```

### Плутанина з пріоритетом and/or

```bash
# ❌ "login or logout and admin" — and має вищий пріоритет,
#    читається як: login OR (logout AND admin)
pytest -k "login or logout and admin"
# ✅ Ставте дужки коли сумніваєтесь
pytest -k "(login or logout) and admin"
```
