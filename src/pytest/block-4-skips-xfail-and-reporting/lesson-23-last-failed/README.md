# Lesson 23: Run Last Failed Tests (`pytest --lf`)

## 🎯 Learning Outcomes

Після цього уроку ви зможете:

- ✅ Розуміти `pytest --lf` (`--last-failed`) — запустити **лише** тести, що впали минулого разу
- ✅ Розуміти роль кешу (`.pytest_cache`) у роботі `--lf`
- ✅ Пришвидшувати цикл дебагу: fix → `--lf` → повторити
- ✅ Знати поведінку `--lfnf` (last-failed-no-failures)
- ✅ Поєднувати `--lf` з іншими опціями (`-v`, `-x`, `-k`, маркери)

---

## 📋 Передумови

Ви вже знаєте:
- Як запускати тести з командного рядка (Lesson 7)
- Маркери та вибірку тестів через `-k` (Block 3)

Тепер ми навчимося **не ганяти весь набір**, а перезапускати тільки те, що впало.

## 📖 Теорія

### 1. Проблема: великий набір, кілька падінь

Уявіть, що у вас 500 тестів. Прогін показав: впало 3.

Ви виправили код і хочете перевірити фікс. Запускати всі 500 — довго й марно: 497 з них уже зелені і навряд чи змінились. Вам потрібні лише ті 3.

Саме цю проблему вирішує `--lf`: **запустити тільки тести, що впали в останньому прогоні.**

---

### 2. `pytest --lf` — лише впалі минулого разу

```bash
# Повний прогін
pytest

# Перезапустити ЛИШЕ ті тести, що впали минулого разу
pytest --lf
# --lf — це скорочення від --last-failed
pytest --last-failed
```

`--lf` бере список впалих тестів з попереднього прогону і запускає **тільки їх**. Решта — пропускається (deselected).

---

### 3. Кеш: `.pytest_cache`

Звідки `--lf` знає, що впало? Pytest **зберігає** результати кожного прогону у теці `.pytest_cache` (у корені проєкту).

- Після прогону pytest записує туди список впалих тестів (node id).
- `--lf` **читає** цей список і запускає лише ці тести.
- Кеш **перезаписується щопрогону** — це завжди «остання картина».

```bash
# де лежить кеш
.pytest_cache/v/cache/lastfailed
```

> ℹ️ Теку `.pytest_cache` прийнято додавати до `.gitignore` — це локальний стан, а не частина коду.

---

### 4. Робочий цикл дебагу

Класичний цикл із `--lf`:

```bash
pytest              # 1. повний прогін → впало 3
# ... виправляємо код ...
pytest --lf         # 2. ганяємо тільки ці 3 → 1 ще червоний
# ... виправляємо далі ...
pytest --lf         # 3. знову тільки впалі → всі зелені
pytest              # 4. фінальний повний прогін — переконатись, що нічого не зламали
```

Кожен крок `--lf` — це секунди замість хвилин. Дуже часто корисно додати `-x` (зупинка на першій помилці) і `-v`:

```bash
pytest --lf -x -v
```

---

### 5. Якщо нічого не впало — `--lfnf`

Що робить `--lf`, коли в кеші **немає** впалих тестів (усе було зелене або кеш порожній)?

За замовчуванням pytest запускає **всі** тести. Це поведінка `--lfnf` (last-failed-no-failures):

```bash
pytest --lf --lfnf all   # (за замовчуванням) немає впалих → запустити всі
pytest --lf --lfnf none  # немає впалих → не запускати нічого
```

Тому **перший** `--lf` без попереднього прогону запустить увесь набір: кеш порожній → «немає впалих» → all.

---

### 6. У QA-роботі

- Швидкий дебаг на великому наборі: локалізували падіння — доганяєте фіксом за секунди.
- Менше очікування, коротший feedback loop.
- Разом з `-x`: зупиняємось на першому ж проблемному тесті.
- Локальна економія часу; у CI зазвичай ганяють повний набір «з нуля».

---

### 7. Зведена таблиця

| Опція | Що робить |
|-------|-----------|
| `--lf` / `--last-failed` | Запустити лише тести, що впали минулого разу |
| `--lfnf all` | Немає впалих → запустити всі (за замовчуванням) |
| `--lfnf none` | Немає впалих → не запускати нічого |
| `--lf -x` | Впалі + зупинка на першій помилці |
| `--lf -v` | Впалі + докладний вивід |
| `.pytest_cache` | Тека, де pytest зберігає результати між прогонами |

## ⚠️ Типові помилки

### Чекати, що `--lf` працює без попереднього прогону

```bash
# ❌ Перший запуск у чистому проєкті — кеш порожній
pytest --lf   # запустить УСІ тести (немає впалих → all)

# ✅ Спершу повний прогін, який заповнить кеш
pytest
pytest --lf   # тепер запустить лише впалі
```

### Видалити `.pytest_cache` і дивуватися

```bash
# ❌ Видалили кеш → історія падінь зникла
rm -rf .pytest_cache
pytest --lf   # знову запустить УСІ (кеш порожній)

# ✅ Кеш потрібен --lf. Не видаляйте його між fix-циклами
```

### Думати, що `--lf` «пам'ятає» назавжди

```bash
# ❌ Хибне уявлення: список впалих зберігається вічно
# Насправді кеш ПЕРЕЗАПИСУЄТЬСЯ щопрогону
pytest        # впало test_b
pytest --lf   # ганяємо test_b, він проходить
pytest --lf   # тепер впалих НЕМАЄ → запустить усі (--lfnf all)
```
